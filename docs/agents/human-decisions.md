# Human Decision Support

The project owner is learning game/software development and should not be asked to invent engineering facts or systems from scratch.

When a skill requires a human decision:

1. Research discoverable facts first: repository state, docs, tests, tooling, and primary external sources when they materially affect the choice.
2. Ask only for preference, product direction, or a hard-to-reverse trade-off that remains after that research.
3. Present 2–4 concrete options with short consequences rather than an open-ended design prompt.
4. Put the recommended option first and explain why it best fits the active Necro trial gate.
5. Make the response easy: the owner should usually be able to answer with an option letter or a small adjustment.
6. Preserve HITL ownership when the active Matt skill requires it; better decision support does not transfer the decision to the agent.

For reversible implementation details inside an approved ticket, prefer a narrow sensible default and verify it rather than interrupting the owner.
